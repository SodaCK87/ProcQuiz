# 檔案結構規範

職責：規定每個檔案放哪、叫什麼、進不進版控。型別：從頭讀型，上限 100 行；超過時把「產出物」以下各節下放到 `docs/檔案結構規範_附錄.md`，原處只留一行連結。

## 頂層資料夾

| 路徑 | 只放 | 何時建 | 進版控 |
| --- | --- | --- | --- |
| `web/` | Vite＋Svelte 網站：`src/`（`App.svelte`、`components/` 元件、`lib/` 純邏輯與其 `*.test.js`）、`prototype/` 定案外觀的原型、前端設定 | 有才建（M2） | 是；`web/dist/`、`web/node_modules/` 否 |
| `tools/` | Python 腳本：下載官方題庫、轉檔與核對、版本差異報告；`tools/review/` 放審查流程的核對腳本 | 有才建（M1） | 是 |
| `tests/` | 轉檔腳本與題庫 JSON 的測試（標準庫 unittest，不另裝套件） | 有才建（M1） | 是 |
| `data/source/` | 轉檔的來源檔：官方題庫 RTF／PDF、第三方解析 xlsx | 有才建（M1） | 是 |
| `data/review/` | 審查定案的卡片註記 `notes.json`（轉檔時掛上題目），經審查流程才能改；`work/` 放審查工作區：法規原文 `laws/`、各輪輸入與產出、`final.json`（`tools/review/` 讀寫，註記的依據指向這裡） | 有才建 | 是：註記的依據與核對腳本都要在任何一台機器重現得出來 |
| `data/questions/` | `tools/` 從 `data/source/` 轉出的題庫 JSON | 有才建（M1） | 是，理由見〈產出物〉 |
| `docs/` | 版本紀錄、問題台帳、本規範；`docs/審查指示/` 放各輪審查給子代理的指示 | 預設建 | 是 |
| `.github/workflows/` | GitHub Pages 部署流程 | 有才建（M3） | 是 |
| `tmp/` | 本機暫存：試算、除錯輸出、差異報告草稿；追蹤檔不得引用 `tmp/` 底下的路徑 | 有才建 | 否，隨時可整個刪掉 |

根目錄只放 `README.md`、`目標路線圖.md`、`CLAUDE.md`、`.gitignore`、`.gitattributes`（來源檔不做換行轉換）、`requirements.txt`（`tools/`、`tests/` 的 Python 相依，釘版；pip 在 Windows 以系統編碼讀它，只能寫 ASCII）。不放 `.gitkeep`：資料夾在第一個檔案出現時才建。不得新增上表以外的頂層資料夾，要新增先改本表。

## 新檔案放哪

依序問，第一個答「是」的就是位置：

1. 只是本機暫存、刪了不影響任何東西嗎 → `tmp/`
2. 是轉檔要讀的來源檔（官方題庫或解析 xlsx）嗎 → `data/source/`
3. 是審查定案、要掛上題目的註記，或審查流程的輸入、指控、中間檔、法規原文嗎 → `data/review/`（後者放 `data/review/work/`）
4. 是 `tools/` 腳本產生的題庫資料嗎 → `data/questions/`
5. 是網站的原始碼、樣式、圖片、前端設定，或網站的建置產出嗎 → `web/`（建置產出固定在 `web/dist/`；網站純邏輯的測試與受測檔同層，`web/src/lib/*.test.js`，用 `npm test` 跑）
6. 是驗證腳本或題庫資料的測試嗎 → `tests/`
7. 是轉檔、報告、審查或維護用的腳本嗎 → `tools/`
8. 是部署流程嗎 → `.github/workflows/`
9. 是文件嗎 → 怎麼用寫 `README.md`；里程碑與不做的事寫 `目標路線圖.md`；這一版改了什麼寫 `docs/版本紀錄.md`；壞掉的東西寫 `docs/問題台帳.md`；審查子代理的指示放 `docs/審查指示/`
10. 以上皆非 → 先問使用者，不得自行開新位置

## 命名

1. 文件檔名用中文；程式、資料、資料夾的檔名用英文小寫，單字以 `-` 連接。法規原文（`data/review/work/laws/`）屬文件，檔名用法規全名。兩個例外：Python 檔用底線（`xlsx_bank.py`，連字號無法 import）；Svelte 元件照框架慣例用 PascalCase（`QuizCard.svelte`）。
2. 日期一律 `YYYY-MM-DD`。
3. 現行版檔名不帶版號，換版直接覆蓋同名檔：官方題庫固定為 `data/source/official.rtf`、`official.pdf`（官方下載名「全部題庫.doc」實為 RTF），解析固定為 `data/source/true-false.xlsx`、`multiple-choice.xlsx`。
4. 版本只有三個來源：官方題庫讀檔內「資料產生日期」，寫進 JSON 的 `generated`；解析讀 xlsx 目錄頁的版次字樣，寫進 JSON 的 `explanationSource`；網站版本是 `web/package.json` 的 `version`，發版時打 git tag `vX.Y.Z`。

## 產出物

| 產出物 | 重建方式 | 進版控 |
| --- | --- | --- |
| `data/questions/*.json` | `python tools/convert.py` | 是。來源檔是二進位，`git diff` 看不出換版改了哪幾題；JSON 的 diff 就是看得懂的換版差異。`tests/` 的 `test_committed_json_matches_regeneration` 守「重跑結果與已提交的 JSON 相同」 |
| `web/dist/` | 在 `web/` 執行 `npm run build` | 否 |

`data/questions/` 不得手改，要修就改 `tools/` 後重跑。

## 廢棄檔

直接刪除，靠 git 歷史找回，不設封存資料夾。舊版題庫不另存副本，從 git 歷史取。

## 不進版控

| 類別 | `.gitignore` 的行 |
| --- | --- |
| Office 開檔時的鎖定檔 | `~$*` |
| 本機暫存 | `tmp/` |
| Python 快取與虛擬環境 | `__pycache__/`、`.pytest_cache/`、`.venv/` |
| Node 套件 | `node_modules/` |
| 網站建置產出 | `web/dist/` |
